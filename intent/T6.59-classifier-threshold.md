## Why

The public-place question "Is the hackathon on going?" was refused because Clef was uncertain. The widget printed the JSON error instead of actionable text.

## Behavior

Clef blocks only when the highest blocked-category confidence reaches the threshold. `EYES_CLASSIFIER_BLOCK_MIN` defaults to 0.95 and accepts finite values from 0.5 through 1 inclusive. Higher means more permissive; 1 is not Off. `createAssessTask(env, blockMin?: () => Promise<number>)` reads the optional getter on every classifier assessment. Invalid environment configuration fails construction; invalid or rejected dynamic configuration fails closed. Deterministic rules and quote-only checks remain unchanged.

Provider errors still fall back to Claude when configured, otherwise return UNAVAILABLE. Claude has no numeric confidence in its schema, so its explicit boolean verdict remains authoritative. No confidence is fabricated.

The shared widget call/error path parses JSON errors and displays escaped message plus fix. Existing OpenAI and MCP Apps bridges, metadata, domains and CSP remain unchanged.

Runtime tests exercise threshold boundaries, dynamic changes, invalid configuration, provider failures and the exact public-place question. The unchanged 200-fixture live run at 0.95 produced 0 false blocks and 62 false allows (precision 1.000, recall 0.415), with no unavailable calls. The exact YC question was allowed. This is not a calibrated or proven-safe setting. The user explicitly accepted this demo trade-off after seeing the result. Original fixtures remain unchanged.

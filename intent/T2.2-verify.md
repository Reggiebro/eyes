## Why
`verifySubmission` checks location, capture freshness and photo content, not answer correctness. Photo moderation rejects only confirmed graphic gore or explicit sexual/adult content. Ordinary scenes and faces pass; uncertainty alone passes. Provider/network/malformed-response failures remain unavailable and require review. Task-request privacy safety is a separate unchanged layer.

## What
- `verifySubmission`: `worker_distance_m` (haversine via `distanceMeters`), `gps_ok`, `fresh_ok`, `vision_ok` + `vision_reason`, `confidence`, `auto_approve = gps_ok && fresh_ok && vision_ok`. Never throws on a vision failure; races `vision.judge` against a 25 s timer so a stalled call is treated as unavailable.
- `createClaudeVision(env)`: `claude-sonnet-5-5` via `@anthropic-ai/sdk` 0.135.0 `messages.parse`, with structured `gore`, `explicit_sexual`, `reason` and `confidence`. Allowed is computed from the two flags; a blocked flag requires confidence >= 0.8 to reject. Photo sent as a URL image block; requires `ANTHROPIC_API_KEY`; 15 s timeout, no retries.
- Added `zod` 4.6.7 (same version as `@eyes/core`) to `@eyes/verify` for the output schema.

## Decisions & alternatives rejected
- GPS rule: `gps_ok = accuracy_m <= 100 && distance - min(accuracy_m, 50) <= task.radius_m`. Reported accuracy buys at most 50 m of slack, so a pass is never more than radius + 50 m from the task (an honest 60 m indoor fix 190 m out still passes a 150 m radius); a fix worse than 100 m never passes on its own, even on the spot. Rejected: ignoring accuracy (fails honest indoor fixes) and slack equal to the full accuracy (follow-up review: a 100 m fix would pass at radius + 100 m).
- Freshness, all against server `received_at`: `received_at <= deadline_at`; `captured_at <= received_at + 60 s` (clock skew); `received_at - captured_at <= 5 min` (live capture, allows typing an answer and a slow upload). Unparseable timestamps fail closed (NaN comparisons are false).
- Vision: ok when the provider returns `allowed: true`; no face flag or confidence gate. clef asks only `gore` and `explicit_sexual` (`noul`, finite [0,1]); >= 0.8 rejects. Real clef failures fall back to Claude if configured, otherwise throw. No required photo gives `vision_ok: false`, reason `no photo`; optional missing photo gives `vision_ok: true`, reason `No photo required`. A thrown or stalled (25 s) call gives `vision_ok: false`, reason `Safety check unavailable; the photo needs manual review.` Only the error name is logged, never private URLs or provider error text. Vision still runs when GPS or freshness fail.
- Confidence: `0.25*gps_ok + 0.25*fresh_ok + 0.5*vision_confidence`, where vision confidence counts only when `vision_ok` and is clamped to [0, 1] (NaN becomes 0). All pass at vision 0.9 gives 0.95; any answer without a judged photo, including an auto-approved no-photo-required one, caps at 0.5 because only location and time were verified.
- Prompt injection: only photo content is sent to the classifier, not the task question, place or worker answer. Visible writing is data to moderate, never instructions.
- Effort `low`: Sonnet 5.5 cannot disable thinking; low effort keeps the judge fast for the waiting worker. Structured output via `output_config.format` (not forced tool use, which Sonnet 5.5 rejects).
- Rejected: the server-side refusal fallback beta (`fallbacks: "default"`). A refusal returns no verdict, `judge` throws, and the submission lands in `needs_review`, which is already safe.

## Assumptions
- No Anthropic vendor note exists. API shapes come from the installed SDK `.d.ts` (0.135.0): `URLImageSource {type:"url", url}`, `messages.parse` + `zodOutputFormat` (`helpers/zod`), `OutputConfig {effort, format}`, client options `timeout` (ms) and `maxRetries`.
- `photo_url` from `Storage.putPhoto` is fetchable by Anthropic (public `captures` bucket direct URL or a presigned URL, docs/vendor/insforge.md Storage). Photos are JPEG/PNG/GIF/WebP.
- `accuracy_m` is browser-reported and spoofable; the cap protects against honest bad fixes, not against cheating.

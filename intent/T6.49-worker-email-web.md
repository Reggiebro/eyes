## Why

Workers can add an optional email as a second channel (T6.46 engine, routes by another worker). A mobile number stays required. The worker web app had no way to enter, confirm, change or remove an email, or to sign in by email.

## What changed

- Join form unchanged: no email field there; workers text their email to Eyes instead (separate task).
- /me: an Email row after the setup rows (it never counts toward "Finish setting up"). none: Add email (inline form), or "Text START first" before START. pending: Check your inbox, Resend link (re-posts the address typed this session, else asks for it again, since the API only returns it masked), Remove. verified: masked address, Change, Remove with an inline confirm. Errors show the API's own message and fix; a 401 shows the expired page.
- /login: "Sign in with email" posts /w/login/email and always says "Check your inbox". The emailed link /login#c=<43-char code> is read from the fragment (cleared at once), traded at POST /w/login/code for the /me code, and opens me.html#c=<token>. A used or expired code says so and offers a new link.
- Hidden until the API serves email: /login probes POST /w/login/email with {} (400 there, 404 before); /me shows no row while GET /w/me lacks email_status.
- `takeCode` takes the code pattern, so /login reuses it.
- docs/features/email-channel.md: status line removed, the try-it steps match the UI (add the email on /me).

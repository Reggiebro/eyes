## Why

The Eyes card (`ui://eyes/card.html`) only displayed results. Its "Ask" button sent a follow-up chat message, and the task card had no buttons. The operator wants the card to act: each button executes the matching MCP tool from inside the chat and shows the result in the same card. The card stays plain HTML, CSS and JS served inline by the connector, with no React and no framework.

## What changed

- `apps/mcp/src/widget.ts`: one `call(name, args)` helper. In ChatGPT it uses `window.openai.callTool`. In other MCP Apps hosts it sends the JSON-RPC `tools/call` request (`{ name, arguments }`) over postMessage, after the existing `ui/initialize` handshake. A JSON-RPC error or an `isError` result rejects. The result is `structuredContent`, or else the JSON text content.
- Buttons:
  - Quote card: a question field plus "Ask for $X" calls `ask_eyes` with question, location, task_type, the quoted bounty and one idempotency key per card.
  - Task card: "Wait for answer" calls `await_answer` (open tasks), "Refresh" calls `get_task`, "Cancel" calls `cancel_task` (dispatched only), "Dispute" plus a reason field calls `dispute_answer` (verified, paid or needs_review answers). Task results merge into the shown task, so the question, place and answer stay.
  - Balance card: "Refresh" calls `get_balance`; "Top up" opens `top_up_url` (`openExternal` or `ui/open-link`), as before.
  - A button is disabled while its call runs. Errors show as a danger notice inside the card, and the button is enabled again.
- `apps/mcp/src/server.ts`: the `tools/list` hook marks the six tools the buttons call (`WIDGET_CALLABLE`) with `"openai/widgetAccessible": true` and `_meta.ui.visibility: ["model", "app"]`. The tools that render the card keep `ui.resourceUri`. Resource metadata (CSP, `openai/widgetDomain`, Claude `ui.domain`) is unchanged.
- The old `say()` follow-up message is removed, because Ask now calls the tool.

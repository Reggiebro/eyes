## Why

The operator wants workers to get tasks by email as well as iMessage, and to sign in to /me by email. To prevent abuse, the phone stays the account: every worker needs a mobile number, each number has one account, and each email belongs to at most one account. Email is an extra channel, never a replacement. An email typed on the join form next to a phone nobody has confirmed must never become a channel, because anyone can type someone else's phone number.

## What changed

- Migration 032 adds `workers.email`, which is unique and stored lowercase, plus `email_verified_at`. `phone` stays NOT NULL.
  - `eyes_join_worker` gains an optional `p_email`. The email is stored only on a new row, and only when no other worker has it. The 5-argument call still resolves, so the running server is unaffected while the migration and the code roll out.
  - `eyes_verify_worker_email` verifies only an opted-in worker, which means the phone has texted START.
  - `eyes_drop_pending_emails` runs from the sweep. It clears a join-form email whose phone has not texted START within 24 hours.
  - `worker_login_codes` holds one live link code per email. Only the SHA-256 of the code is stored, and each code works once.
  - `eyes_worker` and `eyes_set_worker_opt_in` also match the email. STOP by email therefore runs the same path as STOP by text, and STOP also deletes link codes.
  - Dispatch functions (nearby, ping candidates, offer more) also return the verified email.
- Engine changes:
  - Offers, pings, paid notices and ticket notices go to the phone and to the verified email.
  - YES answers on the channel it came from.
  - The phone's first START emails the confirmation link (`/login#c=<code>`, valid 24 hours). The START reply says which address got the link, masked to `j…@domain`.
  - Before the phone confirms, an email START gets "text START from your phone first". An unknown email gets "join with your phone number first".
  - Worker emails set Reply-To to `work@<domain>`, so replies land on Primitive inbound.
- Core changes: `OutboundEmail.reply_to`; optional `email` on `JoinWorkerInput` and `Worker`; `handleWorkerReply({ email })`.
- Stripe Express accounts get the verified email next to the phone.

## Verification

- `engine.int.test.ts` ("email is an extra channel on a phone account"):
  - the pending email gets nothing
  - an email START before the phone confirms neither verifies nor sends
  - the repeat join and the email-taken join both store nothing
  - the phone's START emails the link and masks the address
  - an inbound email then verifies the address
  - offers reach the phone and the verified email, but not an unverified one
  - YES by email gets the capture link by email
  - STOP deletes link codes and the location
  - removing the email clears verification

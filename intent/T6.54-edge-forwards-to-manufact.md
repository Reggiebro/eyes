## Why

Production moves to Manufact Cloud while users keep https://api.eyes.pictures and https://internal.eyes.pictures. The Worker becomes a thin forwarder when ORIGIN is set. Manufact's proxy appends to x-forwarded-for (the last entry would be Cloudflare's egress, one rate-limit bucket for everyone) and may rewrite x-forwarded-host, and the origin is reachable directly, so client IP and host need a header only the Worker can vouch for.

## What changed

- worker.js: with ORIGIN set, every host (workers.dev too) and path goes to ORIGIN with method, headers, streamed body, redirect manual; the response is returned as is (SSE streams). Every request carries x-eyes-client-ip (cf-connecting-ip), x-eyes-host, x-forwarded-host, and x-eyes-edge-secret (env.EDGE_SECRET, empty when unset).
- worker.js cron: with ORIGIN set it only GETs ORIGIN/healthz (errors logged); no ensure(), no Durable Object, so the container never runs next to Manufact's server.
- http.ts: the x-eyes-* headers are always stripped. With EDGE_SECRET set, a request whose secret matches (sha256 + timingSafeEqual) gets x-forwarded-for = x-eyes-client-ip and x-forwarded-host = x-eyes-host; cf-connecting-ip is always dropped (ops-auth falls back to x-forwarded-for); a non-matching request loses x-forwarded-host, its x-forwarded-for is unchanged. EDGE_SECRET unset: behavior unchanged.
- main.ts passes env.EDGE_SECRET; .env.example documents EDGE_SECRET and ORIGIN.

## Switch

`wrangler secret put EDGE_SECRET` (same value as EDGE_SECRET on Manufact), then `wrangler deploy --var ORIGIN:https://<slug>.run.mcp-use.com` from apps/edge/api.

## Verification

- Worker tests: all hosts/paths to ORIGIN with method/body/headers/redirect manual, streamed response passthrough, empty secret when unset, cron pings /healthz and never touches the Durable Object.
- http tests: matching secret trusts x-eyes-client-ip/x-eyes-host; wrong or missing secret drops x-forwarded-host and cf-connecting-ip, keeps x-forwarded-for; no EDGE_SECRET keeps today's headers.

## Why
The process only holds if it is enforced by code: CI rejects a diff that changes product files without an intent file explaining why, and every builder and verifier gets the same written rules instead of a prompt that drifts.

## What
- 16 agent definitions in `.claude/agents/` (1 researcher, 9 builders, 6 verifiers), shared rules in `docs/process/`.
- Hooks in `.claude/settings.json`: block edits to `.env*` (not `.env.example`), and on subagent stop run `pnpm verify:fast` when the branch is `feat/*`.
- `scripts/check-intent.ts`: changed governed files must be listed by an intent file changed in the same diff, intent files need Why and Verification, contract modifications need an ADR, `INDEX.md` must be fresh.
- `docs/SPEC.md` (the build prompt with ADR overrides applied) and `docs/archive/hackathon/STATUS.md`.

## Decisions & alternatives rejected
- Intent check uses only Node built-ins (`path.matchesGlob`, `git` via `execFileSync`).
- Contract rule triggers on modification or deletion, not addition, so a new migration file does not need an ADR.

## Assumptions
- Project hooks and agents load when a Claude Code session starts in this repo. The orchestrator session that created them started elsewhere, so in this session builders get the rules through their prompts and CI enforces the rest.

## Verification
- `guard-env.mjs`: exit 2 on `.env.local`, exit 0 on `.env.example` (run locally).
- `pnpm intent:check` passes on the initial tree.

## Known gaps

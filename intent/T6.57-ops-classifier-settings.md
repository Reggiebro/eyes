## Why
Operators need to change classifier sensitivity in the authenticated internal dashboard without redeploying. A higher threshold requires more confidence that a task is unsafe, so it is more permissive. The default is 0.95; 1.0 is not Off. Rules and classifier failure handling remain the safety package's responsibility.

## Contract
GET /ops/api/settings returns classifier_block_min, default, updated_at, and updated_by. PUT accepts classifier_block_min as a finite number in the inclusive range 0.5 through 1.0 and returns the same projection. The internal host exposes these at /api/settings through the existing host router. Existing allowlisted ops sessions and same-origin mutation protection are reused.

Migration 034 stores only the allowlisted threshold. RLS and revoked public/anon/authenticated grants keep the table and RPCs service-only. An atomic setter records the masked operator and old/new values in the existing events audit log. Missing rows return the default with null audit metadata. Classifier reads cache for 15 seconds; successful local writes invalidate that cache, including in-flight cache-fill races. Database failures propagate to the classifier's fail-closed behavior.

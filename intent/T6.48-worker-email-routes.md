## Why

T6.46 gave workers an optional email next to their phone. The worker web needs HTTP routes to set it and to sign in with it, and the worker's email needs to carry the same messages as the phone in both directions.

## What changed

- `POST /w/me/email {email|null}` with the /me bearer code. Adding or changing the address makes it pending and the engine mails the confirmation link once the phone has texted START. Posting the same address again re-sends the link. `null` removes it. 5 calls an hour per code.
- `POST /w/login/email {email}` always answers `200 {ok:true}` and does not wait for the send, so neither the answer nor its timing shows whether the address is on an account. A body without `email` answers 400 `invalid_input`, which the worker web uses to detect the route. 5 calls an hour per caller address and 5 per email.
- `POST /w/login/code {code}` trades the one-time code from `https://app.eyes.pictures/login#c=<code>` for `{token}`, the /me `e:` token, or answers 401. 10 tries an hour per caller address. The engine keeps codes as hashes, expires them after 15 minutes and accepts each code once.
- `GET /w/me` passes through the engine's `email_masked` and `email_status` (`none`, `pending` or `verified`).
- All three new routes answer `Cache-Control: no-store` and use the existing `/w/*` CORS.
- `withWorkerEmail` wraps Messaging: a recipient containing `@` gets the same text bodies (offer, capture link, already claimed, paid, plain text) by email with Reply-To `work@<PRIMITIVE_DOMAIN>`, and phone numbers keep iMessage.
- Primitive's send API has no Reply-To header, so a `reply_to` on our own domain becomes the From address. Inkbox email already passes `reply_to`.
- Primitive inbound mail to `work@<PRIMITIVE_DOMAIN>` from a DMARC-passing sender goes to `handleWorkerReply({email})`. The reply is the first line above the quoted part, else the subject without `Re:`. The same delivery dedupe applies, and each sender is capped at 20 emails an hour.

## Verification

- `server.test.ts` ("worker email routes (T6.48)"):
  - `/w/me/email` passes the bearer code and trimmed address or null, answers 401 without a code and 400 without `email`, and limits each code to 5 calls an hour
  - `/w/login/email` answers 200 before the send finishes, answers 400 for `{}`, logs a failed send without the address, and limits each address and each caller to 5 calls an hour
  - `/w/login/code` returns the token, answers 401 for a bad code, and stops a caller after 10 tries an hour
- `primitive.test.ts`:
  - a DMARC-passing reply to `work@` reaches `handleWorkerReply` with the lowercased sender, and an unauthenticated one is ignored
  - a redelivery is dropped, and a sender is capped at 20 emails an hour
  - `workerReplyText` handles first lines, quotes, two-line "On ... wrote:" headers, signatures, HTML-only bodies and the subject fallback
  - `withWorkerEmail` emails addresses with Reply-To `work@` and texts phone numbers
  - a `reply_to` on our own domain becomes the Primitive From address

## Known gaps

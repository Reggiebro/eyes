## Why

Primitive sends only to people who emailed us first, so a confirmation link mailed to an address the worker typed is a first-contact send that Primitive refuses. The worker now emails us first, and that email proves the address.

## What changed

- Migration 033 adds `worker_connect_codes`: one live code per worker, SHA-256 at rest, 24 hours, single use. `eyes_connect_worker_email` uses the code and sets the sender as the worker's email, verified, for an opted-in worker. An address another worker has rolls back, so the code stays usable.
- A text from the phone that is `EMAIL`, `e-mail`, or just one email address ("my email is …", `mailto:` and wrapping punctuation are fine) gets "To get tasks by email, tap this and press Send: <short link>". The short link opens `mailto:work@<domain>?subject=Eyes%20<code>&body=Send%20this%20email%20to%20connect`. No email is sent. Before START: "Text START first, then send your email." 5 links an hour per worker. Two addresses in a text are not an email text.
- `EMAIL OFF` removes the email: "Email removed. Eyes won't email you tasks. Text EMAIL anytime to add one again."
- START and HELP add "Text EMAIL to also get tasks by email." while the worker has no email. Step numbering is unchanged.
- Mail to `work@` whose subject has `Eyes <code>` goes to `workerConnectEmail` instead of `handleWorkerReply`, and its answer goes back in the sender's thread from `work@`: "Connected. Eyes will also send you tasks here. Reply STOP to stop.", or an explanation for a taken address or an expired or used code.
- `POST /w/me/email/start` (bearer /me code) returns `{mailto}`, shares `/w/me/email`'s 5 an hour, and refuses before START. `POST /w/me/email` is unchanged (the /me page still uses it to add until it switches to the mailto).
- `withShortLinks` leaves `/s/` links alone (the engine stores the mailto short link itself).

## Verification

- `engine.int.test.ts` ("email by text (T6.51)"): the mailto for `EMAIL`, an address with filler and `e-mail`, and no email sent; START first; wrong, used, expired and taken codes change nothing; the code connects once, verified; the HELP line goes away once connected; the 6th link in an hour is refused; EMAIL OFF removes. START/HELP tests include the new line.
- `primitive.test.ts`: a coded email to `work@` reaches `workerConnectEmail` with the lowercased sender and the answer goes out in its thread from `work@`.
- `server.test.ts`: `/w/me/email/start` returns the mailto uncached, answers 401 without a code, and shares the limit with `/w/me/email`.
- `short-links.test.ts`: an existing `/s/` link is not shortened again.

## Known gaps

- The 5-links-an-hour limit for texts is in memory for each process.
- The join form's optional email still gets a confirmation link after START, as before; Primitive refuses it until any-domain sending is on.

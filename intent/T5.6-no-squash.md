## Why
The owner asked to stop squash-merging. A squash collapses a PR into one commit, so a multi-commit PR like #94 (T6.1 to T6.38) would lose its per-task commits and their author in main's history. SPEC.md still said PRs merge "(squash)".

## What
- docs/SPEC.md: the merge rule says PRs merge with a merge commit and are never squashed.
- Repo settings (not in this diff): squash merging is turned off and merge commits are turned on, titled with the PR title and body.

## Decisions & alternatives rejected
- Merge commit over rebase: rebase rewrites commit hashes that verdict files and STATUS rows cite; a merge commit keeps them.

## Assumptions
- No branch protection rule requires linear history (checked: `required_linear_history` is false, no rulesets).

## Verification
- `gh api repos/ayaangazali/eyes` reports `allow_squash_merge=false`, `allow_merge_commit=true`.
